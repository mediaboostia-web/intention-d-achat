# Tamani — lot 7 (orders)

## Tamani orders (lot 7)

Turning intents into orders and knowing the clients ([plan](../../docs/superpowers/plans/2026-10-28-tamani-07-commandes.md), spec §5.5.1 to §5.5.3); decisions are listed under « Lot 7 » in the roadmap.

- **Model** — `SaleOrder` (migration `9_sale_orders`; the kit's `Order` stays for subscription payments): `responseId @unique` (one order per answer), price frozen in `unitPrice`, `totalAmount` an integer in FCFA, `fulfillment` `DELIVERY | PICKUP`, `status` `TO_CONFIRM | CONFIRMED | FULFILLED | CANCELLED`, `paid` / `paidAt` apart. Deleting a shop or a client cascades; a product with orders is archived by its DELETE route, never deleted (`Restrict`).
- **Shared rules** — [orders-view.ts](../../frontend/src/lib/tamani/orders-view.ts) is pure and used by both sides: `orderUnitPrice` (wholesale price for a `RESELLER` from `wholesaleMinQty`), `ORDER_TRANSITIONS` / `canTransition` (`FULFILLED` and `CANCELLED` are final), `orderActions`, `orderStatusLabel` (« Récupérée » for a pickup), the list filters in the address (`statut=a-confirmer|confirmees|livrees|annulees`, `campagne`, `produit`, `quartier`, `vue=a-livrer`) and `orderWhatsappMessage`. [orders.ts](../../frontend/src/lib/server/tamani/orders.ts) re-exports them for the server.
- **Writes** — `convertResponseToOrder` ([orders.ts](../../frontend/src/lib/server/tamani/orders.ts)) copies a counted « Oui » (product, quantity, buyer type, delivery, zone; the option and an « Autre endroit » place go into the note as « Couleur : Rouge » / « Lieu : X », which every `OrderLine` shows) and is single-shot: `409 ORDER_ALREADY_EXISTS`, `409 RESPONSE_NOT_INTERESTED`, `404 RESPONSE_NOT_FOUND`. `createManualOrder` ([order-queries.ts](../../frontend/src/lib/server/tamani/order-queries.ts)) finds or creates the client by number (the shop's dial code unless `+`/`00`) and only fills a missing first name. `updateOrder` guards status and price writes on the status it read (`updateMany where status`), so the losing tab gets `409 INVALID_ORDER_TRANSITION`; the price changes only at `TO_CONFIRM`, and the same value sent twice is no change. `OrderError` + `orderFailure(err)` carry the codes to the HTTP answer.
- **Reads** — `listOrders`, `ordersToDeliver` (confirmed deliveries grouped by zone, « Sans quartier » last, piece totals per product; `vue=a-livrer` ignores the other filters; pickups are not « à livrer ») and `campaignOrderSummary` (quantities `confirmed`, `fulfilled`, `toConfirm`, and `stockLeft` = stock − confirmed − fulfilled, a display that may go below zero). Rows leave through `toOrderRow` ([serializers.ts](../../frontend/src/lib/server/tamani/serializers.ts)), the client's number masked without `respondentContacts`.
- **Routes** — all `MEMBER`: `/api/shops/[orgId]/orders` (GET list or `vue=a-livrer`, POST manual), `…/orders/[orderId]` (GET, PATCH status / paid / quantity / note / price), `…/campaigns/[campaignId]/orders` (`{ items, nextCursor, summary }`), `…/campaigns/[campaignId]/responses/[responseId]/order` (POST → `201 { order: { id } }`).
- **Reliability and learning** — [reliability.ts](../../frontend/src/lib/server/tamani/reliability.ts): both read only the campaigns a shop followed up, `learnableCampaignWhere(now)`: finished (`finishedCampaignWhere`: `CLOSED`, `ARRIVED`, or `ACTIVE` past `endsAt`), at least one order made from its answers, none still `TO_CONFIRM` or `CONFIRMED` — otherwise a shop that keeps its orders elsewhere would learn 0.1 and see STOP verdicts. `clientReliability` counts those « Oui » answers followed by a `FULFILLED` order, `rate` null under 2 (the card asks `learnableCampaignIds`). `learnedCoefficients` needs 20 « Oui » with a quantity over 2 finished campaigns **per buyer type**, rounds to the hundredth, bounds to [0.1, 1]; `loadLearnedCoefficients` reads the 20 000 newest. `coefficientsFor(org, learned)` uses them only when `PLANS[plan].features.reliability` (Pro and up) — the stats route and `buildHomeBulletin` never load orders on Free.
- **Home** — `TodoItem` gains `CONFIRM_ORDERS` and `DELIVER` (named zones counted), before the arrivals; one `saleOrder.groupBy` in [home-bulletin.ts](../../frontend/src/lib/server/tamani/home-bulletin.ts).
- **Clients** — [clients.ts](../../frontend/src/lib/server/tamani/clients.ts): a visible client is not anonymised and has a counted answer **or** an order (a manual-order-only client has `kind: null` and counts in « Tous » only). `commande=oui|non` (`ordered` in [client-filters.ts](../../frontend/src/lib/tamani/client-filters.ts)) is a non-cancelled order, or none. The card (`getClient`) adds `notes`, the 100 newest `orders`, `totalSpent` (fulfilled orders) and `reliability` (null without `features.reliability`). `PATCH …/clients/[respondentId]` (`MEMBER`) saves the note (1 000 characters, blank → null); `DELETE` (`ADMIN`, `200 { anonymized: true }` — JSON like every shop deletion, since `api()` reads each success as JSON) runs `anonymizeClient` in one transaction: first name, number and note cleared, order notes cleared, a typed `deliveryPlace` turned into « Autre endroit » (stats still count it elsewhere), answers and orders kept and counted; logged as `tamani.client.anonymized` with ids only.
- **Screens** — `/app/commandes` (`OrdersScreen` / `OrderListView` in [OrderList.tsx](../../frontend/src/components/app/OrderList.tsx): status chips, campaign, product and zone filters, the « À livrer par quartier » view; `OrderLine` / `OrderLines` are the shared rows), `/app/commandes/[id]` ([OrderDetail.tsx](../../frontend/src/components/app/OrderDetail.tsx): the total is the bold element, actions from `orderActions`, « Annuler » asks a second tap in a `Notice`, the WhatsApp message prefilled only once confirmed) and `/app/commandes/nouvelle` ([OrderForm.tsx](../../frontend/src/components/app/OrderForm.tsx), price preview from `orderUnitPrice`, pure helpers in [order-form.ts](../../frontend/src/lib/tamani/order-form.ts)).
- **Campaign and clients screens** — each « Oui » row of `InterestedList` has « Transformer en commande » (a ref drops a second tap; on `409 ORDER_ALREADY_EXISTS` the first page reloads) or « Commande créée » with its link (`InterestedRow.orderId`, read through `ROW_SELECT`). The campaign's fifth tab `?onglet=commandes` ([CampaignOrders.tsx](../../frontend/src/components/app/CampaignOrders.tsx)) shows « Stock restant » never below 0 on screen, with its calculation (`stockLeftDisplay` in [results-view.ts](../../frontend/src/lib/tamani/results-view.ts)), then the quantities and the campaign's orders. The client card (`ClientScreen` / `ClientDetailView` in [ClientDetail.tsx](../../frontend/src/components/app/ClientDetail.tsx)): « Total acheté », the orders, reliability on Pro (`reliabilityText` in [client-view.ts](../../frontend/src/lib/tamani/client-view.ts)) or the Pro card, the note (saved on blur or « Enregistrer », one request at a time), and for an `ADMIN` / `OWNER` only « Supprimer les données de ce client » behind a second tap that says it is final, then `router.replace('/app/clients')`. `ClientFilterSheet` gains the « Commandes » select.
- **Deletions answer JSON** — `api()` reads every success with `response.json()`, so a shop route never answers 204: zones `{ deleted: true }`, products `{ archived: true }`, clients `{ anonymized: true }`.
