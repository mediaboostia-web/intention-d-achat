# Tamani — lot 10 (porteur's list)

## Tamani porteur's list (lot 10)

The porteur's bugs and requests of 2026-11-04, simplest first; decisions are listed under « Lot 10 » in the roadmap.

- **Sign-up** — the form asks « Ton prénom » first; `POST /api/auth/signup` takes an optional `firstName` (1 to 60 characters after trim, no control character) into `User.name`. The acceptance line links `/cgu` and `/confidentialite`.
- **Legal pages** — `/cgu`, `/confidentialite`, `/securite`, `/mentions-legales`, all drawn by `LegalPage` from `LEGAL_PAGES` ([legal.ts](../../frontend/src/lib/tamani/legal.ts)): Tamani, a company being registered, Cotonou, Bénin. They describe what the code does: change them with it. The footer links them; `sitemap.ts` lists them.
- **Units** — `COMMON_UNITS` adds pot, verre, boîte, paire, bidon, sachet, mètre; a unit symbol (`kg`, `L`, `cm`…) never takes an « s » (`pluralizeUnit`).
- **Deleting a campaign** — `DELETE …/campaigns/[campaignId]` (`ADMIN`) runs `removeCampaign` ([campaign-remove.ts](../../frontend/src/lib/server/tamani/campaign-remove.ts)): no completed answer and no order → deleted (`{ deleted: true }`); otherwise archived (`Campaign.archivedAt`, migration `9d_campaign_archive`, closed if it was running; `{ archived: true }`), answers, clients and orders kept. Lists, counts, search, the home summary and the bulletin skip archived campaigns; a direct link still opens one. `CampaignDeletion` sits at the bottom of « Modifier » for an owner or admin, behind a second tap.
- **Skeletons** — every loading state of the shop space uses the kit's [Skeleton.tsx](../../frontend/src/components/ui/Skeleton.tsx) (`Skeleton`, `Bone`, and the shapes `CardsSkeleton`, `RowsSkeleton`, `DetailSkeleton`, `FormSkeleton`, `TableSkeleton`, `HomeSkeleton`, `BillingSkeleton`, `NotificationsSkeleton`, `ShopSkeleton`): grey blocks in the shape of what comes, the label read once by a screen reader, no pulse under reduced motion. [skeleton-loaders.test.ts](../../frontend/src/lib/server/observability/skeleton-loaders.test.ts) refuses a « Chargement… » sentence on screen and a screen's own `animate-pulse`.
- **Onboarding** — `/app/bienvenue` asks « Tu es » (Grossiste, Importateur, Les deux, Détaillant — added in lot 11 —, Autre) and « Où tu vends » (Vente en ligne, Boutique physique, Les deux) before the shop form (`WelcomeFlow` in [Onboarding.tsx](../../frontend/src/components/app/Onboarding.tsx); both steps stay mounted). `Organization.businessType` / `salesChannel` (migration `9e_shop_profile`, null for older shops; values and words in [shop-profile.ts](../../frontend/src/lib/tamani/shop-profile.ts)); `POST /api/shops` and `PATCH /api/shops/[orgId]` accept them, `toShop` sends them, Réglages shows two selects (« À choisir » until set; never back to null).
- **Contact consent** — the popup's contact step has an unticked, optional box « J'accepte que {boutique} me contacte sur WhatsApp… » (`consentLabel` / `consentNote` in [popup-copy.ts](../../frontend/src/lib/tamani/popup-copy.ts), link to `/confidentialite`), sent as `contactConsent`. `Respondent.contactConsentAt` (migration `9f_contact_consent`; clients recorded before keep their number) is set by a ticked box or a manual order; an unticked box never takes an earlier yes back. Every number leaves the server through `shownPhone(e164, canSeeContacts, consentAt)` ([contact.ts](../../frontend/src/lib/server/tamani/contact.ts)): without consent, no number on any plan (rows carry `contactRefused: true`, screens say « Numéro non partagé », the CSV « Non partagé »), no digit search, no numbers export. The answer still counts everywhere else. `upsertResponse` answers `contactShared` (consent now or on an earlier answer), kept in the phone's `SavedAnswer`: only then does the thanks dialog promise a WhatsApp call (`thanksCopy`). The contact step's title is `contactTitle` (« Pour réserver ta commande » for a product in stock).
- **Quantities per option** — on a product with options (colours or sizes), the popup's quantity step is `OptionQuantityStep`: a − / number / + line per option, the total, « Valider » once it is above 0 (a product without options keeps the presets). It sends `optionQuantities: [{ option, quantity }]` (1 to 12, each a product option, 100 000 pieces in all); the server writes the total in `quantity`, the option in `option` when only one is chosen, the split in `Response.optionQuantities` (JSON, migration `9g_option_quantities`); a bare quantity clears it, a « no » too. Rules in [option-split.ts](../../frontend/src/lib/tamani/option-split.ts): `optionSplit(r)` reads a split (an older answer is one line from its option), `optionText` writes « Rouge × 3, Noir × 2 » where the option used to go (interested list, client card, export, the order's note « Couleur : … »); the stats count each option of a split apart. The estimate, the verdict and the money read the total, unchanged.
- **Pushes and payment (PR #15)** — `requestCheckout` builds the pass checkout (`api()` encodes the body; [api-body.test.ts](../../frontend/src/lib/server/observability/api-body.test.ts) refuses `body: JSON.stringify`), the bell panel is fixed below `lg`, see lot 5 for the push test.
